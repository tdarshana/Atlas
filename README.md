# Atlas

Shared memory and agent hub for coding agents (Claude Code, Codex, Claude, DeepSeek and OpenRouter-based agents). Rust daemon with DuckDB storage, MCP over stdio and HTTP, a CLI with a TUI, and a Tauri 2 desktop app.

## Install

    cargo install --path crates/atlas-cli --locked
    cargo install --path crates/atlasd --locked

## Connect agents

    claude mcp add --scope user atlas -- atlas mcp

Codex, in `~/.codex/config.toml`:

    [mcp_servers.atlas]
    command = "atlas"
    args = ["mcp"]

Any MCP client that speaks streamable HTTP can use `http://127.0.0.1:7433/mcp` once `atlas daemon start` has run.

## Connect a project

    cd repo
    atlas project connect
    atlas sync

`atlas project connect` registers the repository with Atlas and builds a profile from it: languages, frameworks, a file tree, the README head, recent commits. `atlas sync` then writes what Atlas knows about the project into it:

- One agent file per saved agent: `.claude/agents/<name>.md` for Claude Code, `.codex/agents/<name>.toml` for Codex. Each opens with a `generated by atlas; edit in Atlas, not here` marker, and `sync` refuses to overwrite a file in either directory that lacks it, so a hand-written agent is never clobbered.
- A managed block in `AGENTS.md` and `CLAUDE.md`, delimited by `<!-- atlas:start -->` and `<!-- atlas:end -->`. Only the text between those markers belongs to Atlas; the rest of the file is left untouched.

`atlas sync --check` reports what would change without writing, and exits 1 if anything would. `atlas sync --global` writes the same agent files into your home directory instead of a project.

Once synced, saved agents show up as Claude Code and Codex subagents: Claude Code reads `.claude/agents/*.md`, Codex reads `.codex/agents/*.toml`.

## CLI

    atlas remember "we deploy to fly.io" --kind decision --tag infra
    atlas recall "where do we deploy"
    atlas project connect
    atlas agent save reviewer --description "Reviews pull requests" --instructions-file reviewer.md
    atlas sync
    atlas daemon status

`atlas project`, `atlas agent`, `atlas practice` and `atlas workflow` manage the corresponding library with `list`, `show`, `save` and `delete` subcommands (`project` has `connect`, `list` and `show`). `atlas export DIR` writes the whole library to `DIR` as JSONL and Markdown; `atlas import DIR` reads it back. Full flags in `docs/usage.md`.

Data lives in `~/.atlas/atlas.duckdb`. Set `ATLAS_HOME` to relocate it. See `docs/usage.md` and `docs/superpowers/specs/2026-09-02-atlas-design.md`.
